# IndustrialDryingChamberControl 
  Суть проекта
Модель конвейерной сушильной камеры. Полный цикл: нагреть камеру → включить конвейер → поддерживать температуру гистерезисом → при Stop/E-Stop/аварии остановить нагрев и конвейер, включить вентиляцию и вытяжной клапан.
Проект, третий по счёту. Цель — собрать архитектуру смешанного управления: аналоговый тракт, машина состояний, аварии, ручной арбитраж, журнал событий и статистика. ST — средство, не цель.
Архитектура
PLC_PRG — диспетчер: входы, HMI watchdog, порядок вызова FB, выходы на IO/HMI.
FB_SignalConditioning — аналог: raw → EngValue, Valid, debounce, FilteredValue.
FB_DryerController — главный FB: состояния, аварии, предупреждения, журнал, авто-команды, ManualAllowed.
FB_Manual — арбитраж AUTO/MANUAL/безопасность.
FB_Statistics — статистика: время ТЭНа/конвейера, циклы, uptime, счётчики аварий.
  Режимы
AUTO — штатная сушка.
MANUAL — только в Idle и при связи с HMI.
Stop — мягкая остановка, возврат в Idle.
E-Stop — аварийный останов: нагрев/конвейер OFF, вентиляция/клапан ON, Aborted.
  Приоритеты защит
E-Stop
Range Check / повреждение состояния
Перегрев
Обрыв/невалидность датчика
Нет нагрева
Потеря связи HMI
Аналоговая часть
RawValue — сырой АЦП.
EngValue — масштабированное значение.
FilteredValue — значение для управления и гистерезисов.
Valid — валидность сигнала.
Debounce защищает от одиночных помех.
  Машина состояний
Initial → Idle → Heating_UP → Holding → Aborted.
Idle ожидает Start.
Heating_UP греет ТЭН и вентилятор до порога конвейера.
Holding поддерживает температуру и управляет конвейером гистерезисом.
Aborted выходит только после Reset и снятия активных аварий.
Defense in Depth
Неизвестное состояние → Aborted.
Барьеры после CASE ограничивают выходы.
Гистерезис синхронизирован с состоянием машины.
Ручной режим не пересчитывает диагностику, а получает готовые флаги.
Статистика считает final-команды, поэтому наработка верна и в AUTO, и в MANUAL.
  Диагностика и журнал
ErrorCode — текущая авария.
WarningCode — текущее предупреждение.
aAlarmHistory — последние 10 событий.
Журнал пишет события по фронту появления, не по уровню.
Дубликаты подряд не пишутся, повтор после другого события разрешён.
Clear History очищает только архив; текущее состояние видно в ErrorCode/WarningCode.
Статистика
Время работы ТЭНа и конвейера.
Циклы сушки каждые 10 минут движения конвейера.
Общее время работы системы.
Счётчики аварий по каждому типу.
Счётчики аварий считаются по переходу FALSE → TRUE, а не каждый скан активной аварии.
  Ключевые принципы
Один владелец на структуру: stStatus у контроллера, stStatistics у статистики.
Контроллер создаёт события, статистика их считает.
FB_Statistics вызывается после FB_Manual.
PLC_PRG не содержит бизнес-логики, только связывает блоки.
VAR — состояние между сканами, VAR_TEMP — расчёт одного скана.
RETAIN — для счётчиков, наработки и циклов; R_TRIG — нет.
   Особенности
MANUAL только в Idle.
Нет Complete: цикл завершается Stop или Aborted.
Материальный трекинг не реализован.
Учебный период задачи — константа; на заводе брать фактический цикл.
Статистика отделена от управления, журнал отделён от текущего статуса.
